# Replaying the scheduler analysis

The public files contain normalized stage names, capture-relative examples and aggregate counts. The decoder expects little-endian x86-64 Linux, a C++17 compiler, Python 3.11 or newer and NumPy. This decoder supports the fixed-buffer 64-bit kernel records and image identities in these particular captures. Use the *expanded* ETL bytes matching the following SHA-256 values.

| Input | Expanded ETL SHA-256 |
|---|---|
| C08 | 1ff6431f55a159748044917b618e3f601cc3eb60ae8d194e961968eb3d444b79 |
| C09 | 4248a3cb70349cfa6dd6813e418c52a95ab4cf27a9d8e75230ae7761139dac40 |
| C05, optional positive control | 48292c0fe2212556f50d98f23e1375c27e30a70b3fefa6fe7e7389fac0d23cb6 |

From this directory, point the arguments at the local ETL files. Use separate directories for transient private records and the aggregate CSV output.

```sh
python replay.py --c08 /data/C08.etl --c09 /data/C09.etl --c05 /data/C05.etl \
  --scratch ./private-replay --out ./replayed
```

The wrapper verifies each digest, compiles the decoder, summarizes the samples and scheduler events, and writes the CSV files below. The private scratch directory contains raw time counters, thread identities and CPU IDs. Only the output CSV files are intended for distribution.

| Output | Interpretation |
|---|---|
| release-cpu.csv | A partition of physical samples from identified game thread IDs. Matched stacks can include an external leaf. The mapped-leaf column restricts this to game or mod Burst instruction leaves. Unmatched or otherwise unselected samples fall under Other. |
| entry-runs.csv | Sample count on the process entry thread and longest consecutive sampled span. Every sample must belong to the same class with no intervening switch of that thread and no gap over 1.3 ms. |
| release-waits.csv | Waiting-state switch-out intervals paired with exactly one ReadyThread before switch-in. Thresholds use blocked time up to readiness and are nested. An unmatched interval can only be bounded by its total off-CPU duration. |
| wake-activity.csv | Counts by most recent activity on the readying CPU, sensitivity to 0.5 ms versus 1.0 ms, three-sample matches, and first-to-last sample spans. Rows partition waits per capture and threshold. The sustained, half-wait and duration fields apply only to the selected named jobs. |
| wake-examples.csv | Longest sustained sampled span per selected activity among waits of at least 5 ms. Time zero is the first physical sample on an identified game thread. |
| seller-lookup.csv | Seller-job samples in the PE unwind range and subset with one of the seven first-caller return RVAs listed in summarize_wakes.py. |
| infoview-control.csv | C05 check against the previously identified heavy vanilla Apply episodes. The first UnityPlayer frame is image-relative. |

The scheduler join uses per-CPU CSwitch history at the event timestamp. A disagreement with a header source thread prevents the recent-sample join. Exact physical-sample joins require coincident sample timestamp, thread ID, instruction pointer and a stack from the game PID. Job classification uses the outermost game or mod frame. For a shared pathfinding job, branch return addresses distinguish ordinary routes, availability and coverage. A replacement DLL instruction leaf identifies the mod. Correlation with ReadyThread never fills an unsampled gap by searching backward past another physical sample. A readier that runs another job between successive sample ticks can still be misclassified.

All seven CSVs, including the control, were regenerated byte-for-byte from the expanded ETLs in a separate directory. No game process was started.

## Optional symbol verification

The shipped job-roots.csv is sufficient for replay. To check its managed job identities independently, use a .NET 8 SDK, the historical managed references and Burst 1.8.23. The historical Game.dll SHA-256 is `721e7e17bf74299aa2b988c1bd07e90874bb8bc72d263229500c4bf639e7e4ee`. The helper uses Burst's own closed-producer resolver, method encoder and Hash128 implementation. Its project expects the Burst package's .Runtime directory. The final command verifies the actual export names and relative addresses in the recorded game Burst PE with GNU objdump.

```sh
dotnet build symbols/VerifyJobs.csproj -p:BurstRuntime=/data/burst/.Runtime --artifacts-path /tmp/scf-symbols
dotnet /tmp/scf-symbols/bin/VerifyJobs/debug/VerifyJobs.dll \
  /data/historical/Managed /data/burst/.Runtime job-roots.csv
python symbols/verify_exports.py /data/lib_burst_generated.dll
```
