# Large Apply queue screening and confirmation

The accepted change in 0.3.6 applies `MethodImplOptions.AggressiveInlining` to `ByteTakeWinner`. Stock Burst 1.8.23 emitted this helper as a separate call from the radix loop. Both current native targets removed the out-of-line helper after the change. The C# selection, readiness tests, coverage arithmetic, diagnostics, and the 12,436-byte fixed directory are unchanged. The earlier producer is from `0920e76`.

## Method

The 24-round holdouts used the current `f076df4b...` game's own native Apply producer as an output oracle and newly compiled baseline/candidate producers. The preliminary 7-, 9-, and 11-round screens used stock and mod workers compiled against the historical `721e7e17...` file. All runners use Unity Burst 1.8.23 on AMD EPYC 9V74 Linux x64, pinned to logical CPU 6. Each fixture compared target bytes to vanilla, verified unchanged input elements and allocation guards, and compared workload counters across all candidates before timing. The separate standard differential logs cover all 3,072 generated cases and two large tie cases per current target. The timed region is the complete worker, including filter/sort, provider selection, Apply arithmetic and diagnostics. Input reset, game scheduling, rendering, and disk access fall outside that region. These are offline generated inputs.

Each implementation executes the same input in each round. The three final comparisons also balance AB and BA within every adjacent pair of rounds. Ratios use the median of `baseline / candidate` across matched rounds. The budget fixture by design repeats a fixed seed, 1878. The other shapes take their generator seed from the filename. Seed 351 replays the published interleaved/ties fixture. Seeds 8317 and 9341 are fresh. Only the 8317 holdout uses SSE4. The per-shape CLI labels `inter` and `ties` use `Inputs.Make` with benchmark mode. `richinter`, `mixed`, and `runs` use ShapeTimings' corpus with unquantized full overlap, random narrow overlap and long separated runs. The 64-provider `ties` row uses `Inputs.Make` with eight discrete values. Counts and visit history refer to candidate/oracle verification in the included logs or the release's separate integrated evidence.

## Selection and limitations

The historical screens compare 33 distinct native alternatives. `screen` varies radix digit width and replaces per-bucket minima with prefix redistribution. `screen2` coarsens leaf keys by 2–7 bits while retaining full stable order within each leaf. `screen3` defers ordered Apply visits in batches of 8–64, with and without early destination-pointer loads. `screen4` varies forced inlining, alias annotations, out-of-line redistribution, and a direct two-node path. `screen5` tests directory packing and selective minimum tracking. Exact leaf bins gained up to ~13% on fully interleaved parks but regressed finite budgets, and deferred execution lost on dense ties and clustered runs. Directory changes offered no consistent extra gain over forcing the call inline. Only that annotation was selected. Screen and holdout rounds share this host and realistic distributions in an actual city remain unknown.

Current held-out heavy interleaved speedups were 1.082–1.101×, budget 1.093–1.115×, other full-overlap 1.071–1.089×, mixed 1.075–1.080×, and clustered runs 1.065–1.077×. The current 526-provider eight-way tie fixture ranged from 0.985× to 1.003×. The 64-provider SSE4 eight-way tie fixture measured 0.971×. A single-provider control excluded the changed branch.

`summary.csv` includes every fixture and tested alternative. `hold-*.csv` and `screen*.csv` retain every worker timing in milliseconds. `current-manifests.json` preserves worker hashes and exports. The candidate DLL build uses the functionally identical, fully qualified spelling of the attribute. Other integration changes and the final mod receive their own release-level verification.

## Reproduction

Build the provided `reproduce/Bench.csproj` with .NET 8. Compile stock, 0.3.5 and inline candidate using the repository's `tests/compile_managed.py` and `tests/burst_compare/compile_worker.py` with matching game Managed directory, Burst runtime and architecture. Put the three worker directories at `<directory>/{vanilla,base,inline}/{AVX2,X64_SSE4}` and set `SELECTOR_WORKERS` to the common parent. Run `dotnet reproduce/bin/Release/net8.0/Bench.dll 8317 24 X64_SSE4 base inline` and replace `8317 24 X64_SSE4` with `351 24 AVX2` or `9341 24 AVX2` for the other holds. The reproduction driver emits raw comma-separated rows without a header. In the archived CSVs the first row names the columns.
