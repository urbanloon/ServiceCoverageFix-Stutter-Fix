# Independent stock and 0.3.6 worker verification

The 0.3.6 source was taken from commit `6c4c7f4` and 0.3.5 from `0920e76`. The isolated managed builds used the .NET 8.0.408 SDK, Harmony 2.2.2 net48 and game references supplied by the user. Unity Burst 1.8.23 ran on Microsoft.NETCore.App 10.0.0. The isolated runners used Microsoft.NETCore.App 8.0.15. The host reported an Intel Xeon Platinum 8573C. Timings were pinned to logical CPU 7. Other work on the host continued on other CPUs.

## Files

| File | Contents |
|---|---|
| native-worker-identities.csv | Input assembly SHA-256, linked worker SHA-256 and actual producer export for each rebuild |
| native-checks.csv | Exact event comparison, native target bytes and counts, exceptional-float modes and large-provider checks |
| native-three-way.csv | Medians and paired wall-clock ratios across 24 balanced three-worker rounds |
| native-samples.csv.gz | All 432 measured triplets for 18 workload/target combinations |
| windows-byte-identity.log | Fresh PE hashes and the historical COFF timestamps that reproduce the two archived hashes |

The current, historical and September game SHA-256 prefixes were `f076df4b`, `721e7e17` and `aaee15c4`, respectively. Recompiling the managed 0.3.6 mod against each game produced `b8c8a7d6494839bda0445af05098d94c1d2841c3fa107dd45368993284748a6d`. Each stock/0.3.6 pair matched all 2,750 exact ordering fixtures on its game. Each also matched all native output and workload checks on both Linux ISAs, including 24 total combinations of game, ISA and denormal mode. The actual Options widget, patch-contract, contract mutation and lifecycle checks are recorded in `native-checks.csv`.

The visit-order probe ran the actual instrumented game and mod IL on identical inputs. It compared the original element index on each visit and both float bit patterns and destination on each write, preserving their interleaving. Independently compiled native jobs compared complete final target arrays, immutable inputs, out-of-bounds guard bytes and four reported work counters against an oracle derived from stock visits. Floating-point runs selected preserve, DAZ, FTZ or both flags in MXCSR before executing both workers.

The timing suite runs vanilla, 0.3.5 and 0.3.6 in all six execution orders. For each input it checks stock output before timing. The measured section covers the native worker and harness invocation. It excludes input reset, game scheduling, pathfinding, rendering and presentation. The order statistics are individual paired ratios, not confidence intervals. The machine showed substantial wall-time dispersion. For the 526-provider AVX2 budget job the paired vanilla/0.3.6 median was 12.27× (3rd–22nd of 24 rounds, 8.63–16.54×). For interleaved paths it was 16.30× (11.80–22.74×) and for dense ties it was 2.02× (1.27–3.77×). These fixtures establish stock-worker savings. The small differences between the two mod versions are poorly resolved on this run.

## Reproduction

Follow `tests/burst_compare/README.md` for compilation, both Linux targets and Windows link-only checks. Build the two mod assemblies with `tests/compile_managed.py` and the versioned source trees above. Use the 0.3.6 DLL produced against the current build when running it against any game assembly. Generate a fresh stock-visits CSV on each game with `tests/visit_order`, then use that game's CSV for its native workload oracle. For the three-worker runs pass `--require-nan --budget --three-way`, with the 0.3.6 and 0.3.5 directories in that order, and point `CS2_BURST_VANILLA` to the matching stock directory. Compile `tests/burst_compare/set_denormal_flags.c` as described in the harness guide and run `--require-nan` under each of the four modes and instruction targets. All suite inputs are generated. Official Windows mod postprocessing, Unity scheduling and live frame delivery require separate in-game verification.

## Road-overlap order and counter cost

The additional road-overlap IL oracle uses seed 83951 and the same four input generators as `tests/park_overlap`. Across all four inputs the stock worker executed 3,335,457 visits and 63,096 destination stores. The local and citywide cases each consumed all 1,111,964 entries and wrote all 6,128 distinct park slots. The tied case consumed 1,109,953 entries and wrote all 6,128. The tight-budget case consumed 1,576 entries and wrote 1,392 distinct slots. Distinct slots can receive several writes. See `overlap-order.log`. To repeat the independent trace, run `python3 overlap_trace.py REPO EMPTY_BUILD_DIRECTORY GAME_MANAGED MOD_DLL 83951` with the .NET 8 SDK on PATH.

The empty 0.3.6 job used an additional median 13.7 ns of thread CPU on AVX2 and 11.4 ns on SSE4 with a valid counter pointer. All five nonempty shapes showed paired timing dispersion that included 1.0 on each ISA. This test changes only the job's existing nullable diagnostics argument. On the enabled path the same producer updates Started, Workload and Completed. It retains the same merge, work-count arithmetic, code placement and allocations in both arms. It excludes the managed diagnostics bridge and any game scheduling cost. The 32 balanced rounds per shape use the stock outputs as the reference and verify counters, guards and results after every batch. See `counter-cost.csv` and `counter-samples.csv.gz`. Build `counter-probe/CounterProbe.csproj` with `-p:RepoRoot=/absolute/path/to/repo`, then run the resulting DLL with the original Managed folder and matching stock and 0.3.6 Linux worker directories as its three arguments.

## Two-competitor experiment

The independently recompiled two-competitor DLL has SHA-256 `9181b7e563c576e53d328320780772ccc93bd70b61eec4b7f84461946c924eb5`. Each of the three game versions matched the candidate's combined visit and write trace on both the 2,750-case suite and the four packed road-overlap inputs. The current game's additional five-case scattered layout, including mixed provider budgets, matched 3,892,251 visits and 81,883 stores. Mixed alone issued 556,794 visits and 18,787 stores across all 6,128 roads. Replicate the latter with `PARK_OVERLAP_LAYOUT=scattered` and append `--shapes local,citywide,mixed,ties,tight` to the trace command. Worker identities and cross-build results appear in `pair-workers.csv` and `pair-checks.csv`.

The independent native holdout used seed 682731 with 18 measured rounds per shape. Each six-round block ran all six orderings of vanilla, 0.3.6 and the candidate on the same data. All three workers matched stock destination bytes throughout. The two mod runs reported identical workload counts. Each row in `pair-overlap-summary.csv` gives worker medians and paired 0.3.6/candidate ratios. For 18 rounds the indicated lower/upper order statistics are the second and seventeenth smallest ratios. The raw elapsed and thread-CPU readings are in `pair-overlap-samples.csv.gz`. Reproduce with `tests/park_overlap`, rounds 18, seed 682731, shapes `local,citywide,ties,tight`, packed layout and the matching vanilla, 0.3.6 and candidate workers in that order.

## Pointer-sampling experiment

The AVX2 pointer-sampling DLL had SHA-256 `5ef6bb3c185cde1a4ce040f84fa0711f5396b7d7591109ca82d37870c7541228`. It passed the native workload oracle on the current game and the five-input scattered managed trace. The independent four-worker packed-layout timing used seed 921137, in vanilla/0.3.6/direct-pair/gated argument order. It recorded 18 rounds per shape. The summary uses the first 16 rounds (two complete eight-order rotation/reversal blocks), with all 18 retained in the raw samples. The gated job took 95.7 μs median thread time on tight-budget inputs, compared with 85.3 μs for direct pair. The median paired direct/gated ratio was 0.938×. The other direct/gated ratios were 0.966× local, 0.976× citywide and 1.033× tied. The individual paired ranges included 1.0 throughout. These measurements supply an independent control for the cost of choosing the queue strategy dynamically. See `gated-overlap-summary.csv`, `gated-overlap-samples.csv.gz`, `gated-scattered-order.log` and `gated-current-native.log`.
